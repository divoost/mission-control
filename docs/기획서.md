# Mission Control — DevHUD · 기획서

> 한 줄: **Claude Code로 만드는 모든 프로젝트의 완성도·막힌 곳·다음 할 일을 한눈에 관리하는 AI 개발 관제센터.**
> 모든 수치는 로컬 실데이터(git · Claude Code 로그)에서 나오며, 가져올 수 없는 것은 **지어내지 않습니다.**

---

## 1. 제품 개요

| 항목 | 내용 |
|---|---|
| 무엇 | git 저장소 + 로컬 Claude Code 로그를 읽어 개발 현황을 SF 관제화면(HUD)으로 보여주는 로컬 대시보드 |
| 누구 | 여러 프로젝트를 동시 개발하는 사람 · AI 코딩으로 제품 만드는 1인 창업자 · 개발팀/PM·대표 |
| 왜 | GitHub 트래픽(스타/클론)도 CPU/RAM도 아닌 **"이 프로젝트 지금 어디까지 왔나"**를 답하는 화면이 없었다 |
| 어떻게 | 파이썬 표준 라이브러리 서버가 git 읽기전용 명령 + 로컬 로그를 읽어 단일 HTML HUD로 제공 |
| 보안 | `127.0.0.1`만 바인드 · git 구조/카운트만 읽음 · **`.env`·키·시크릿 절대 안 읽음** · 외부 전송 없음 |
| 라이선스 | MIT · 의존성 0 (pip 설치 불필요) |

공개 저장소: https://github.com/divoost/mission-control

## 2. 차별점 (경쟁 대비)

유사 Claude Code 모니터들이 있으나, Mission Control의 핵심은 **"정직한 완성도 관리"**:

1. **기능(등록) 완료율 ↔ git 추정 분리 표기** — 많은 도구가 git 성숙도(문서/테스트/CI)를 완성도처럼 보여줘 과대평가를 유발. 우리는 둘을 나란히 보여줘 오해를 막는다. (완료율은 등록 기능 기준이며 코드·테스트 자동 검증은 아님을 명시)
2. **위험 감지** — 장기 정체·반복 수정·되돌림(revert)·테스트 없음·오류를 **실제 신호에서만** 자동 감지.
3. **비개발자 보고서(경영 요약)** — 대표·PM이 10초에 "오늘 뭐 했나 / 뭐가 막혔나 / 다음 뭐 하나"를 이해. 전문용어 없이, 복사해서 바로 전달 가능.
4. **정직성** — 실데이터만. 못 가져오는 것(claude.ai 채팅, 타 AI 도구)은 표시하지 않는다.

→ 단순 "모니터"가 아니라 **AI 개발 프로젝트 운영관리 도구**로 포지셔닝.

## 3. 기능 구성

### A. 자동 감지 (zero-config · git)
마일스톤 · 단계(Phase) · 기능 상태 · 기술 스택 · 코드 구성 · 모듈 구조 · DB 테이블 · 화면 · 문서 · 브랜치 · 기여자 · 커밋 활동(14일) · 작업 분포 · 커밋 레이더 · TODO/FIXME

### B. 실시간 작업 (Claude Code 로컬 로그)
세션별 주제 · 최근 액션(수정/작성/실행) · 파일 편집 ±라인(세션 로그 기준) · 편집 실시간 스트림 · 작업 상태(활성~3분/최근/유휴, 추정) · 토큰 사용량(입/출/캐시)
> claude.ai **채팅** 프로젝트는 API가 없어 자동 표출 불가 → 수동 보드로만.

### C. AI 프로젝트 관리 레이어
- **기능(등록) 완료율** — 등록 기능 done/total (git 추정과 분리)
- **개발 보고서** — 오늘/7일 커밋 · 변경 파일(git) · 열린 TODO
- **다음 할 일** — 진행중/미착수 기능 · 코드 TODO · 미완료 마일스톤 (실제 신호만)
- **위험 감지** — 장기 정체 · 반복 수정(churn) · revert · 테스트 없음 · TODO 과다 · Claude 로그 오류
- **경영 요약(비개발자 보고서)** — 평이한 문장 + 복사 버튼

### D. 종합(Overview)
전체 집계 · 프로젝트 카드 · 지표 링 세부↔종합 순환 · 콘솔 로그(DB/모듈/화면/문서)

### E. 선택 기능 (opt-in, 기본 꺼짐)
Anthropic API 토큰·비용(Admin 키) · 내 프로젝트 수동 보드 · 활동 주제 숨김(`activityTopics:false`)

### F. UX
6개 언어(EN/KO/VI/JA/ES/ZH) · 4 테마 · 모션(우주 도넛·입자·지표 순환·콘솔 로그) — 연출은 의도적, 숫자는 진짜

## 4. 아키텍처

```
브라우저 (단일 index.html, HUD)
   │  polls
   ▼
http.server (stdlib, 127.0.0.1, 의존성 0)
   ├─ /api/status    프로젝트별 git 상태
   ├─ /api/overview  전체 집계 + 기능완료율 + 콘솔로그 + 지표분해
   ├─ /api/report    개발 보고서 · 다음 할 일 · 위험 감지
   ├─ /api/activity  Claude Code 세션 활동 · 파일 편집 · 작업 상태
   ├─ /api/claude-usage  로컬 토큰 사용량
   ├─ /api/api-usage     Anthropic Admin API(선택)
   └─ /api/my-projects   수동 보드(선택)
   │
   ├─ git (읽기전용) ──→ 각 저장소
   └─ ~/.claude/projects/*.jsonl (세션 로그)
```

- **설정**: `config.json` (git-ignored) · `config.sample.json` · `MC_CONFIG` 환경변수로 외부 경로 지정 가능
- **안정화**: 포트 충돌 시 자동 다음 포트 · git 미설치 경고 · 스캔 시간 예산(기본 6초) · 캐시(mtime/TTL)

## 5. 데이터 출처 · 정직성 (검증 가능)

| 수치 | 출처 | 검증 |
|---|---|---|
| 기능 완료율 | config features done/total | done ÷ 전체 (코드·테스트 검증 아님) |
| 커밋·변경파일 | `git log` | 동일 git 명령과 대조 |
| DB 테이블 | `.sql` CREATE TABLE / `.prisma` model | 스키마 파일 count |
| 토큰 | 로그 `message.usage` 합산 | jsonl usage 합계 |
| 위험 | git/로그 실제 신호 | 아래 §6 테스트 |

**원칙**: 실데이터만 · 못 가져오면 표시 안 함 · 완료율↔git추정 병기 · 출처 뱃지(REAL·LOCAL/GIT/API) · 시크릿 미접근.

## 6. 테스트 (자체 검증)

`test_server.py` — 표준 `unittest`만 사용(의존성 0). 실행:

```bash
python3 test_server.py
```

- **순수 함수**: 주입 문구 필터 · 라인수 계산 · 액션 라벨 · 토큰 분류
- **빈 상태 안전**: 로그 없을 때 크래시 없음
- **git 픽스처**: 임시 저장소로 DB 테이블 수 · 기능 완료율(1/3→33%) · TODO 감지 · 위험(churn/notest) · 다음 할 일 · repo 탐색 검증

→ 현재 **15개 전부 통과**. Mission Control이 경고하는 "테스트 없음"을 스스로 해결(dogfooding).

## 7. 설치 · 실행

```bash
git clone https://github.com/divoost/mission-control.git
cd mission-control
cp config.sample.json config.json     # scanDirs가 repo를 자동 감지 (선택적으로 repo 지정)
python3 server.py                     # pip 설치 없음
```
→ http://127.0.0.1:8799 (포트 사용 중이면 자동으로 다음 포트). repo가 하나도 없으면 **첫 실행 온보딩**이 설정 방법을 안내.
